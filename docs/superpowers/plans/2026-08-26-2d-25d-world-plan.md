# Deadworld 2D/2.5D Isometric World Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a high-quality hybrid 2D/2.5D isometric renderer with eight separately authored directional sprite views, layered character compositing, natural illustrated props, a 9x authoritative streamed world and 60 FPS mobile/desktop validation.

**Architecture:** Retain Godot's 2D CanvasItem pipeline and build focused presentation systems around a shared sprite contract. The server and client consume a versioned cell-based world descriptor; server simulation remains authoritative while the client activates visual cells and proxy layers by relevance. Asset generation is deterministic and validates dimensions, pivots, direction completeness, alpha, atlas padding and memory before Godot import.

**Tech Stack:** Godot 4.7.1/GDScript, existing Nakama + TypeScript runtime, PostgreSQL persistence, Python standard library for deterministic sprite/atlas generation, PNG atlases, CanvasModulate/PointLight2D, Node test runner, TypeScript strict check.

**Spec:** `docs/superpowers/specs/2026-08-26-2d-25d-world-design.md`

## Global Constraints

- No `MeshInstance3D`, `Skeleton3D`, GLB or runtime 3D renderer.
- `96x128 px` character frame, 8 directions, 6-8 frames per state.
- Directions are `N, NE, E, SE, S, SW, W, NW`; no mirroring as a missing-direction substitute.
- Shared layer pivot is bottom-center at feet contact.
- `1 world grid cell = 1 gameplay metre`; streaming cell is `32 x 32` metres.
- Server remains authoritative for position, collision, bounds, spawns, items, containers, zombies and persistence.
- Target is 60 FPS on desktop and modern mid-range Android/iPhone devices around Snapdragon 7 Gen 1 / Apple A15 or newer.
- Mobile budgets: 180 active sprite layers, 32 animated characters, 4 PointLight2D nodes, 256 MB visible textures, 9 active cells.
- Desktop budgets: 360 active sprite layers, 64 animated characters, 8 PointLight2D nodes, 512 MB visible textures, 25 active cells.
- No external runtime asset packs or services.

## Rollback

- Keep the existing renderer behind a debug flag until Task 9 passes.
- Roll back client presentation independently from authoritative schema migration if visual QA fails.
- Keep v1 descriptor reader and deterministic persisted-position repair for one release cycle.
- Do not delete old item/container records or assets during migration.
- If performance fails, reduce cells/clutter/lights/texture resolution before lowering the 60 FPS target.
