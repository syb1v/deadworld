# 2026-08-19 — Визуальный редизайн и релизная матрица

## Цель

Project Deadworld перестаёт выглядеть как технический прототип и начинает читаться как атмосферный изометрический survival, соответствующий GDD §6 (камера сверху под углом, tile/grid world, динамический свет, ограниченная видимость).

Проверяемый результат:

- камера следует за игроком, мир больше не показан целиком статичным экраном;
- мир построен из сгенерированного тайлсета с изометрической подачей вместо цветных прямоугольников;
- динамическое освещение и ограниченная видимость создают напряжение;
- единая мрачная постапокалиптическая палитра во всех системах;
- HUD игровой: иконки предметов, слоты, читаемые индикаторы состояния вместо отладочного текста;
- релизы содержат только целевые платформы.

## Границы

**In scope:** `client/` presentation layer, генерация ассетов, `scripts/`, `.github/workflows/`, `docs/`.

**Out of scope:** server authority, wire protocol (остаётся `1`), persistence, gameplay-правила, баланс, новые механики.

## Текущая архитектура (факты)

- `client/scripts/world/WorldMap.gd` рисует мир через `_draw()` заливками из `client/data/world_map.json`.
- `client/scripts/entities/{Player,Zombie,WorldItem,Container}.gd` рисуют сущности примитивами в `_draw()`.
- Камеры нет: `Boot.tscn` держит статичный `1280x720`, весь мир виден сразу.
- `client/assets/` содержит только `icon.svg`.
- HUD в `Boot.tscn` — текстовые `Label`, инвентарь выводится строками.
- Сервер берёт геометрию мира из того же `world_map.json` (`server/src/world.ts`), поэтому визуальные изменения не затрагивают коллизии и авторитетность.
- Релизная матрица сейчас: Linux x86_64/x86_32/arm64/arm32 (tar.gz+deb+rpm), Windows x86_64/x86_32/arm64 (exe+zip), Android APK, iOS IPA.

## Принятые решения

1. **Гибридный визуал** (решение пользователя): окружение, свет, тени и атмосфера — процедурно; предметы, иконки инвентаря и UI-элементы — сгенерированные ассеты.
2. **Изометрическая подача без смены системы координат.** Сервер остаётся в декартовых координатах; изометрия применяется только на слое отображения. Иначе пришлось бы менять коллизии и протокол, что вне scope.
3. **Единая палитра как данные.** Один ресурс палитры, из которого берут цвет все системы, вместо хардкода hex по файлам.
4. **Ассеты генерируются скриптом в репозиторий** и коммитятся, чтобы сборка не зависела от генерации в CI.
5. **Целевая матрица релизов:** Android universal APK, Windows x86_64 + arm64 (exe), Linux x86_64 + arm64, iOS IPA. Остальное удаляется.

## Задачи

### Этап 1 — фундамент визуала
1. `client/data/palette.gd` — единая палитра постапокалипсиса (земля, бетон, ржавчина, кровь, акцент, свет).
2. `scripts/generate_assets.py` — генератор PNG: тайлы поверхностей, иконки предметов, UI-элементы. Детерминированный, без внешних зависимостей.
3. Сгенерировать и закоммитить ассеты в `client/assets/`.

### Этап 2 — мир и камера
4. `client/scripts/world/GameCamera.gd` — слежение за игроком, ограничение по границам мира, мягкий lookahead по прицелу, зум под платформу.
5. Переписать `WorldMap.gd`: тайловая отрисовка поверхностей, изометрические объёмные стены со скосом и тенями, мусор/декали, вертикальная сортировка.
6. Подключить камеру в `Boot.tscn` и `World.gd`.

### Этап 3 — освещение и атмосфера
7. `client/scripts/world/Atmosphere.gd` — слой освещения: ограниченная видимость вокруг игрока, затемнение краёв, световые пятна, лёгкая зернистость.
8. Тени сущностей и подсветка источников света.

### Этап 4 — сущности
9. Перерисовать `Player.gd`, `Zombie.gd` в единой палитре с изометрическим силуэтом, тенями и читаемыми состояниями.
10. `WorldItem.gd`, `Container.gd` — иконки из сгенерированных ассетов, подсветка интерактивной цели.

### Этап 5 — HUD
11. Игровой HUD: слоты хотбара с иконками, индикаторы здоровья/патронов, читаемый prompt взаимодействия.
12. Панель контейнера с иконками вместо текстового списка.
13. Главное меню в едином стиле.

### Этап 6 — релизная матрица
14. Урезать `client/export_presets.cfg` до 5 пресетов.
15. Обновить `Makefile`, `scripts/package_release.py`, `.github/workflows/ci-release.yml`.
16. Обновить landing (`admin/server.mjs`) и его тест.

### Этап 7 — документация и проверка
17. `docs/ART_DIRECTION.md` — арт-направление, палитра, правила.
18. Обновить `README.md`, `docs/ARCHITECTURE.md`, `docs/ROADMAP.md`, `docs/MVP.md`.
19. Полный regression suite, проверка сборок, релиз.

## Acceptance criteria

- `make test` зелёный, включая существующие клиентские тесты.
- Godot экспорт проходит для всех 5 целевых пресетов.
- Протокол не изменён: `PROTOCOL_VERSION = 1`.
- Сервер и коллизии не затронуты.
- Релиз содержит ровно 5 платформенных артефактов + checksums.
- Скриншот-проверка: мир, свет, HUD визуально соответствуют GDD §6.

## Проверки по этапам

- После этапа 1: генератор детерминирован, ассеты импортируются Godot.
- После этапа 2: клиент запускается, камера следит, границы не выходят за мир.
- После этапа 3: производительность не деградирует на mobile-профиле (gl_compatibility).
- После этапа 4–5: headless parse без ошибок, клиентские тесты проходят.
- После этапа 6: локальная упаковка даёт ровно ожидаемый набор файлов.
- После этапа 7: полный suite + реальный релиз с независимой проверкой артефактов.

## Rollback

Все изменения — presentation layer и упаковка. Откат = revert коммита; серверные данные и persistence не затрагиваются. Удалённые пресеты восстанавливаются из истории git.

## Discovered / Later

- Звуковой слой (шаги, выстрелы, окружение) — отдельная задача v0.1.1.
- Анимационные состояния через AnimationPlayer вместо процедурных.
- Погода и цикл дня/ночи — v0.2, требует серверного времени мира.
